# CapCar SEO audit: 100 workflows

Capture date: **23 October 2026** (Europe/Berlin). Target: `https://capcar.dev`.
Goal: install reusable project SEO workflows and assess all 100 roles in the
supplied infographic. Working markets: English/German first; structural checks
cover English, German, Greek, Albanian and Japanese.

Source checkout reviewed: `e3c72a40976eb72ff9d899824a2f5c8869803211` on `master`.
Master advanced during the run to `7b7675f5a1ac1a625e29175111bcac0eb19d61ee`
(“Focus the homepage hero on an automatic concept reveal”). Its changed-file
list and new hero copy were reviewed; this PR is based on that newer commit.
The live deployment is separately observed and is not assumed identical to an
earlier source snapshot. This run assessed workflows sequentially in one assistant session,
reusing evidence. It did not launch 100 independent worker processes.

## What matters first

The public site's core technical SEO is in place: **115/115 sitemap URLs return
HTTP 200**, with unique titles, descriptions, one H1, self-canonicals and the
expected reciprocal language annotations in the captured HTML. The homepage
and articles deliver appropriate structured data. No site-wide indexability
blocker was verified in this snapshot.

The useful next work is establishing actual search/activation measurements,
finishing localized instructions, making the specialist directory useful before
promoting it, and adding authentic owner evidence. A separate used-car business
also uses the CapCar name; consistent app/category identity is sensible, but this
audit cannot establish the cause of a particular Google ranking.

Disposition across all 100 roles: **47 done, 31 partial, 17 blocked, 5 not
applicable**. `done` means the workflow completed within its stated scope, not
that a page passed every SEO criterion. Every partial/blocked result names its
unverified remainder. See [the complete role ledger](2026-10-23-results.md).
No overall SEO score, traffic forecast, backlink authority, rankings or CWV
values are supplied without the corresponding evidence.

## Checks that should be retained

- All 115 sitemap pages have one self-canonical after normalizing an empty root
  path to `/`. The root `https://capcar.dev` versus `https://capcar.dev/` spelling
  difference is equivalent and is not counted as a canonical defect.
- Each exposes `en`, `de`, `el`, `sq`, `ja` and `x-default`; targets and reciprocal
  annotations agree in the captured graph. No duplicate titles were found.
- HTTP and www samples use one 301 to HTTPS/apex. Sampled English feature aliases
  use one 308 to the unprefixed URL. `/journal` uses a 307 to `/en/journal` in this
  English request context, consistent with locale resolution.
- The sitemap excludes login/private garage destinations. `/login` delivers
  `noindex, follow`; no private garage records were inspected.
- Homepage JSON-LD contains `WebSite`, `Organization` and `SoftwareApplication`.
  Journal articles contain `BlogPosting`, brand publisher/author identity,
  localized canonical context and real supplied dates. JSON parsing is checked,
  but external vocabulary/rich-result validation is not claimed.
- No genuine app rating/review evidence was supplied. Google requires a rating
  or review for software rich-result eligibility; no false stars are proposed.
  The free-beta offer and provider-cost caveats must remain scoped truthfully.
- Product copy distinguishes illustrative budgets, owner records, reference
  models/recordings, conditional fitment and provider-dependent planning.
- A Sound Studio parameter sample retains its clean canonical. The entire
  library's crawlable pagination is unverified; decide its search purpose before
  creating individual indexable recording pages.

## Remaining uncertainty and validation

The early HTTP homepage had the H1 “Keep your car's plans and history together.”
The later desktop browser had “See the build. Make it happen.” A follow-up HTTP
request using both Mozilla and audit user agents also contained the newer text.
The new master commit `7b7675f` contains exactly that newer hero copy, and its
changed-file list was reviewed before basing this PR on it. The source, later
browser and fresh HTTP agree. This is capture/deployment drift, not evidence
of cloaking or a hydration bug. The baseline preserves
the distinction rather than silently replacing the earlier measurement.

No current CrUX/lab CWV data, actual indexing/selected canonicals, organic query
metrics, acquisition/conversion data, complete backlink profile, review history,
controlled AI citation sample or numerical forecast is available. Task-level
SERP gaps and comparable software competitors were not audited. Local GBP/NAP/
pack/service-area/branch checks do not apply without a separately identified
eligible local business. No schedule or outreach was created.

The verifier checks 101 suite manifests, all role IDs, metadata, local references,
explicit invocation policies, collisions against existing project names and the
100-result ledger. No application code changed, so no app build/test pass is
claimed for this documentation/skills-only PR. The actual Codex loader was additionally verified during publication as recorded
above; discovery in the Mac's current session remains a local step.
